==============================================================
3. TOK DAT (WORKFLOW)
==============================================================

  1. Pouzivatel nastavi kriteria (config/criteria.yaml alebo UI)
  2. Agent vola: search_real_estate_portals + search_auctions
  3. Pre KAZDY pozemok -- pipeline_service.analyze_parcel():
       ensure_coordinates()     -> GPS suradnice (geocoding_service)
       run_gis_services()       -> 7 GIS sluzieb (feature flagy)
         distance_service       -> vzdialenost od BA
         flood_service          -> Q100 zaplavova zona
         terrain_service        -> sklon, zosuvy, radon
         bpej_service           -> bonita pody, ochrana, odvody
         overpass_service       -> cesta, elektrina, voda, okolie
         protected_service      -> VVN/VTL, Natura 2000, CHKO
         zbgis_service          -> geometria (sirka, tvar, vymera)
       run_price_service()      -> price_analysis_service EUR/m2
  4. scoring_service            -> vazene skore 0-100
  5. Ak skore >= 70:
       cadastral_service        -> manualny LV checklist (B/C/D)
  6. report_service             -> investicny report + text
  7. notifier_service           -> email / Telegram (prah skore, feature flag)

  Odolnost pipeline:
    Vypnuta sluzba  -> ServiceResult.skip_result (neutralne 50)
    Vynimka sluzby  -> ServiceResult.error_result (pipeline pokracuje)


==============================================================
4. SCORING ALGORITMUS
==============================================================

  Kriterium             | Vaha (predvolena, menitelna v YAML)
  ----------------------|--------
  Cena (EUR/m2)         | 18 %
  Vzdialenost od BA     | 12 %
  Infrastruktura        | 20 %
  Pravna proxy          | 18 %
  Zaplavove riziko      | 10 %
  Bonita pody (BPEJ)    |  8 %
  Teren                 |  7 %
  Chranene uzemia       |  7 %

  >= 85 -> STRONG BUY    >= 70 -> INVESTIGATE
  >= 50 -> CONSIDER      <  50 -> SKIP

  Vahy:   config/criteria.yaml -> scoring -> weights
  Prahy:  config/criteria.yaml -> scoring -> thresholds

==============================================================
7. UROVNE AUTOMATIZACIE
==============================================================

  AUTO   = agent zvladne plne, bezi paralelne, bez cakania
  SEMI   = agent pripravi 90%, vy spravite 1 krok (napr. CAPTCHA)
  MANUAL = agent vygeneruje checklist/ziadost, vy overite rucne

  AUTO:   vzdialenost, zaplavy, teren, BPEJ, chranene uzemia,
          infrastruktura (OSM), bonita pody, cenova analyza
  SEMI:   List vlastnictva B/C/D (CAPTCHA katasterportal.sk)
          Uzemny plan (UP/UPI) -- OCR + LLM extrakcia
  MANUAL: kapacita trafostanice (ZSDIS)
          archeologicka zona (KPU)

==============================================================
10. REST API ENDPOINTY  (Flask, port 5001)
==============================================================

  GET  /api/health                 -> status, pocet sluzieb, verzia
  GET  /api/config/                -> kriteria, vahy, prahy, features
  GET  /api/config/validate        -> overenie criteria.yaml
  POST /api/analyze                -> analyza 1 pozemku (JSON -> report)
  POST /api/parcels/analyze-batch  -> analyza N pozemkov, zoradene

  POST /api/analyze - vstup:
    { title, price_eur, area_sqm, location_text,  <- povinne
      url?, parcel_number?, lat?, lon? }           <- volitelne

  POST /api/analyze - vystup:
    { parcel: {...}, report: {text_report, recommendation, ...} }
