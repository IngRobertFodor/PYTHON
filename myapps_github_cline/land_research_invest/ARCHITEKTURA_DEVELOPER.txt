3. TOK DAT (WORKFLOW) — DVOJFAZOVY SCORING
==============================================================

  --- FAZA 1: SCRAPING + LACNY PRE-SCORING (0 HTTP, okamzite) ---

  1. Pouzivatel nastavi kriteria (config/criteria.yaml alebo UI)
  2. scraper_service.scrape_all()
       -> 7 zdrojov paralelne (ThreadPoolExecutor):
            nehnutelnosti_sk, topreality_sk, reality_sk
            spf, ske_drazobne_vyhlasky, notarske_drazby
            obchodny_vestnik
       -> dedup podla (url + parcel_number)
       -> vysledok: list[Parcel] (typicky 2000-5000 kusov)
  3. scoring_service.preliminary_score() pre KAZDY pozemok (0 HTTP):
       price_score    (35%) -> cena v konfigurovanom rozsahu
       area_score     (30%) -> vymera v konfigurovanom rozsahu
       ppsm_score     (20%) -> EUR/m2 pod limitom
       source_bonus   (10%) -> drazbove zdroje = bonus (podhodnotene)
       data_quality   ( 5%) -> penalizacia za chybajuce polia
     -> parcel.preliminary_score (0-100) + prelim_recommendation
  4. Zoradeny zoznam (tabulka) + filter (zdroj / cena max / vymera min)
     Pouzivatel zafajkne kandidatov (max 30)

  --- FAZA 2: PLNY GIS SCORING VYBRANYCH (HTTP, ~20s/parcelu) ---

  5. POST /api/scrape/score-selected {urls: [...]}
     Pre KAZDU vybranú parcelu -- pipeline_service.analyze_parcel():
       ensure_coordinates()     -> GPS suradnice (geocoding_service)
       run_gis_services()       -> 8 GIS sluzieb paralelne (feature flagy):
         distance_service       -> vzdialenost od BA (Haversine)
         flood_service          -> Q100 zaplavova zona (SHMU WMS)
         terrain_service        -> sklon, zosuvy, radon (DMR/SGUDSH)
         bpej_service           -> bonita pody, ochrana, odvody
         overpass_service       -> cesta, elektrina, voda, okolie (OSM)
         protected_service      -> VVN/VTL, Natura 2000, CHKO
         zbgis_service          -> geometria (sirka, tvar, vymera)
       run_price_service()      -> price_analysis_service EUR/m2
  6. scoring_service.score_parcel() -> vazene skore 0-100 + recommendation
  7. Ak skore >= 70:
       cadastral_service        -> manualny LV checklist (B/C/D)
  8. report_service             -> investicny report + text
  9. notifier_service           -> email / Telegram (prah skore, feature flag)
  10. Mapa zobrazena len pre skórovane parcely (maju GPS)

  Odolnost pipeline:
    Vypnuta sluzba  -> ServiceResult.skip_result (neutralne 50)
    Vynimka sluzby  -> ServiceResult.error_result (pipeline pokracuje)


==============================================================
4. SCORING ALGORITMUS
==============================================================

  --- FAZA 1: LACNY PRE-SCORING (scoring_service.preliminary_score) ---

  Kriterium             | Vaha  | Zdroj dat
  ----------------------|-------|---------------------------
  Cena v rozsahu        | 35 %  | parcel.price_eur
  Vymera v rozsahu      | 30 %  | parcel.area_sqm
  EUR/m2 pod limitom    | 20 %  | parcel.price_per_sqm
  Bonus drazbovy zdroj  | 10 %  | parcel.source_portal
  Datova kvalita        |  5 %  | price_eur>0 AND area_sqm>0

  -> parcel.preliminary_score (0-100) + prelim_recommendation
  Rozsahy z criteria.yaml: price.min/max_eur, parcel.min/max_area_sqm

  --- FAZA 2: PLNY GIS SCORING (scoring_service.score_parcel) ---

  Kriterium             | Vaha (predvolena, menitelna v YAML)
  ----------------------|--------
  Cena (EUR/m2)         | 18 %
  Vzdialenost od BA     | 12 %
  Infrastruktura        | 20 %
  Pravna proxy          | 18 %
  Zaplavove riziko      | 10 %
  Bonita pody (BPEJ)    |  8 %
  Teren                 |  7 %
  Chranene uzemia       |  7 %

  >= 85 -> STRONG BUY    >= 70 -> INVESTIGATE
  >= 50 -> CONSIDER      <  50 -> SKIP

  Vahy:   config/criteria.yaml -> scoring -> weights
  Prahy:  config/criteria.yaml -> scoring -> thresholds

7. UROVNE AUTOMATIZACIE
==============================================================

  AUTO   = agent zvladne plne, bezi paralelne, bez cakania
  SEMI   = agent pripravi 90%, vy spravite 1 krok (napr. CAPTCHA)
  MANUAL = agent vygeneruje checklist/ziadost, vy overite rucne

  AUTO:   vzdialenost, zaplavy, teren, BPEJ, chranene uzemia,
          infrastruktura (OSM), bonita pody, cenova analyza
  SEMI:   List vlastnictva B/C/D (CAPTCHA katasterportal.sk)
          Uzemny plan (UP/UPI) -- OCR + LLM extrakcia
  MANUAL: kapacita trafostanice (ZSDIS)
          archeologicka zona (KPU)

10. REST API ENDPOINTY  (Flask, port 5001)
==============================================================

  --- Analyza pozemkov ---
  GET  /api/health                 -> status, pocet sluzieb, verzia
  GET  /api/config/                -> kriteria, vahy, prahy, features
  GET  /api/config/validate        -> overenie criteria.yaml
  POST /api/analyze                -> analyza 1 pozemku (JSON -> report)
  POST /api/parcels/analyze-batch  -> analyza N pozemkov, zoradene

  --- Scraping + dvojfazovy scoring ---
  GET  /api/scrape/progress        -> stav scrapingu (running, %, per-source)
  POST /api/scrape/start           -> spusti scrape_all + pre-scoring (background)
  GET  /api/scrape/results         -> vysledky (preliminary_score DESC)
  POST /api/scrape/score-selected  -> plny GIS scoring vybranych {urls:[...]}
  GET  /api/scrape/score-progress  -> stav plneho scoringu (done/total/%)

  POST /api/analyze - vstup:
    { title, price_eur, area_sqm, location_text,  <- povinne
      url?, parcel_number?, lat?, lon? }           <- volitelne

  POST /api/analyze - vystup:
    { parcel: {...}, report: {text_report, recommendation, ...} }

  POST /api/scrape/score-selected - vstup:
    { "urls": ["https://...", ...] }  max 30 URL
