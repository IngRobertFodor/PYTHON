WHAT CHANGED
------------
requirements.txt was updated:
  BEFORE: pypdf>=6.14.2
  AFTER:  pypdf==6.14.2

The version is now pinned exactly to 6.14.2, which is a safe version
above the fix threshold of 5.1.0. This prevents any downgrade to a
vulnerable version.


HOW TO APPLY THE FIX
--------------------

Option A: Using system Python / pip
------------------------------------
1. Open a Command Prompt in this project folder
2. Run: pip install --force-reinstall pypdf==6.14.2
3. Verify: pip show pypdf

Option B: Using install_dependencies.bat (reinstall all dependencies)
----------------------------------------------------------------------
1. Double-click install_dependencies.bat
   (This will install all packages from requirements.txt, including
   the pinned safe version of pypdf)

Option C: Using the bundled WinPython
--------------------------------------
1. Open a Command Prompt in this project folder
2. Run: WinPython\python-3.x.x.amd64\Scripts\pip.exe install --force-reinstall pypdf==6.14.2
3. Verify: WinPython\python-3.x.x.amd64\Scripts\pip.exe show pypdf


VERIFY THE FIX
--------------
After installation, check:
  pip show pypdf

Expected output:
  Name: pypdf
  Version: 6.14.2


REBUILD THE EXE (if distributing as standalone application)
-----------------------------------------------------------
If you distribute this app as a .exe file (built with PyInstaller):
1. Apply the fix above first
2. Rebuild: pyinstaller --onefile main.py
   (or use your existing .spec file)
The rebuilt .exe will include the patched pypdf version.
